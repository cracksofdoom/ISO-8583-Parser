MESSAGE FLOW
How a message is read
The decoder starts at the front of the frame and uses the bitmap to know which fields to read next. Field definitions and encodings can vary by payment network.

      

        
01 / IDENTIFY
Read the MTI
The four-character Message Type Indicator describes the message version, class, function and origin. For example, 0200 commonly represents a financial transaction request.

        
02 / LOCATE
Check the bitmap
Each bit maps to a data-element number. A set bit means that field is included. The first bit can signal that a secondary bitmap follows.

        
03 / DECODE
Read data elements
Fields are interpreted in numeric order using each element’s format and length rules—fixed, variable, numeric, text or binary.

      

    


    

      
01 / MESSAGE TYPE INDICATOR
MTI — the message’s intent
The MTI is four digits. Each position adds context about the message, rather than describing a transaction field.

      

        
0Version2Class0Function0Origin
EXAMPLE MTI0200
Financial transaction request

        

          
DIGIT 1
Version
Identifies the ISO 8583 version family used by the message.

          
DIGIT 2
Message class
Broad category such as authorization, financial, reversal, reconciliation or network management.

          
DIGIT 3
Message function
Indicates whether it is a request, response, advice, notification or another message role.

          
DIGIT 4
Message origin
Describes where the message originated or its role in the exchange, depending on the version/profile.

        

      

      
0200 Financial request0210 Financial response0400 Reversal request0800 Network managementExamples are common conventions; exact MTI usage depends on your network.

    


    

      
02 / FIELD PRESENCE MAP
Bitmap — the message’s index
The bitmap is a compact sequence of bits. It does not carry field values; it tells the receiver which data elements appear in the payload.

      

        
PRIMARY BITMAP · 64 BITSHEX VIEW
12345678910111213141516171819202122232425262728293031323334353637383940414243444546474849505152535455565758596061626364
 Set bit = field included Unset bit = field omitted
Bit 1 is a special indicator: when set in the primary bitmap, a secondary bitmap is present.

        
Primary bitmap
Usually covers DE 1–64. The first bit is used to indicate whether a secondary bitmap follows; in many profiles DE 1 is not treated as an ordinary field.
Secondary bitmap
Extends the map to DE 65–128. Its presence is signaled by the primary bitmap’s first bit.
Why it matters
Without the bitmap, the receiver cannot reliably know which fields are present—or where the next field begins when lengths vary.

BACKGROUND
What is ISO 8583?

      
ISO 8583 is an international standard for exchanging electronic messages between systems involved in card-based financial transactions. It defines a message structure and conventions for carrying transaction information, including requests, responses, reversals and network-management messages.
Think of it as a shared envelope and vocabulary for payment messages. The standard provides the structure, while individual payment networks and processors define the detailed field rules, values and operational behavior used in their environment.
Parser helps developers and analysts explore that structure, troubleshoot integrations, and compare message frames. Always validate decoded fields against the specification for your processor or network.
